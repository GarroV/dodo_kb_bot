# Dodo KB Bot

Telegram-бот-прослойка для доступа партнёров Dodo Pizza к внутренней Базе Знаний
(knowledgebase.dodois.io) — без выдачи партнёрам личных логинов или личных
MCP-токенов.

## Что это и зачем

Партнёр пишет вопрос боту на человеческом языке. Бот прогоняет вопрос через LLM
(gpt-5.6-luna) с доступом к read-инструментам MCP-сервера Базы Знаний
(`search_content`, `get_content`, `get_space_content`, `get_announcements`,
`get_spaces`, `current_user`, `get_link_templates`, `preview_content`) —
LLM сама решает, идти ли в базу, какой инструмент вызвать и как сформулировать
поиск, а затем пересказывает найденное обычным языком со ссылками на источник,
а не отдаёт сырой JSON.

**Поиск идёт в две фазы, и это важно.** `search_content` возвращает только
заголовки и короткие обрывки текста (excerpt) — по ним модель обязана лишь
*выбрать* статьи, а затем прочитать их целиком через `get_content` и отвечать
только по полному тексту. Без этой фазы модель домысливает шаги, которых в
статье нет (проверено вживую — получались «советы» вместо инструкции).
`search_content` — поиск по ключевым словам, не по смыслу, а часть материалов
существует только на английском, поэтому для международных тем промпт требует
второй запрос с английскими терминами.

**Единая точка входа.** Один сервисный PAT-токен от Базы Знаний живёт только в
`.env` на сервере — партнёры его никогда не видят и не получают. Соединение
read-only: без заголовка `Mcp-Mode: Write` сервер Базы Знаний вообще не отдаёт
write-инструменты в `tools/list` (проверено вживую) — значит запись физически
недоступна из этого бота, а не просто отключена по договорённости.

**Кто может писать боту.** Списка допущенных партнёров нет. Личка для вопросов
закрыта — бот отвечает только в групповых чатах, куда он добавлен, и только по
явному обращению (`@упоминание`, reply или команда `/kb_ask`). Контроль доступа
на уровне того, кто добавляет бота в чат, а не на уровне самого бота. См. риск
в «Не решено / предстоит».

## Стек

| Слой | Технология |
|---|---|
| Бот | Python 3.12, aiogram 3, long polling (без вебхука) |
| LLM | OpenAI gpt-5.6-luna, tool-calling (модель задаётся `OPENAI_MODEL`) |
| MCP-клиент | официальный `mcp` (Python SDK), Streamable HTTP |
| Хостинг | Docker Compose на своём сервере (long polling, вебхук не нужен) |
| Хранилище | нет своей БД — контент живёт во внешней Базе Знаний; единственное, что копится локально, — счётчик транзакций/токенов (`usage.jsonl` в Docker volume) |

Архитектура и цикл tool-calling — по образцу `handleAsk` из проекта Swarm Brain
(`supabase/functions/swarm-bot/handlers/knowledge.ts`), адаптированы под чужой
MCP вместо собственной Supabase-базы.

## Быстрый старт

```bash
cp .env.example .env
# впиши BOT_TOKEN (@BotFather), OPENAI_API_KEY, KB_MCP_TOKEN (выдаёт админ БЗ)

docker compose up -d --build
docker compose logs -f bot
```

## Личка vs групповой чат

- **Личка закрыта для вопросов.** `/start` и любой текст в личке получают в
  ответ короткое сообщение «пиши в групповом чате» — вопрос через LLM не
  уходит. Исключение — команда `/stats`, она разбирается отдельно и работает
  только в личке (см. ниже).
- **Групповой чат** — вопрос обрабатывается тремя способами:
  1. `/kb_ask <вопрос>` — самый надёжный: команды Telegram доставляет боту
     всегда, даже если у бота включён Group Privacy Mode (стоит по умолчанию
     у новых ботов и не даёт Telegram передавать боту простой текст с
     упоминанием, пока явно не выключишь через @BotFather).
  2. `@упоминание` бота в обычном тексте.
  3. reply на сообщение бота.

  Варианты 2 и 3 требуют выключенного Group Privacy Mode — иначе Telegram
  отфильтрует такие сообщения ещё до бота, и `bot/group_gate.py` их просто не
  увидит. Всё, что не попало ни под один из трёх способов (болтовня партнёров
  друг с другом), молча игнорируется — гейт `bot/group_gate.py`, порт паттерна
  `lib/group-gate.ts` из Swarm Brain (плюс триггер по reply, которого там не
  было).
- Команды (`/start`, `/stats`, `/kb_ask`) гейту группового чата не подчиняются
  — их сама Telegram Bot API различает по `/command` или `/command@имя_бота`.
- **`/stats` пиши в личку боту**, не в общий чат: это единственное, что личка
  всё ещё принимает, и счётчик токенов не будет светиться перед партнёрами в
  общем чате.

## Счётчик транзакций и токенов

Каждый ответ дописывает одну строку в `usage.jsonl` (внутри Docker volume
`usage_data`, не в git): timestamp, кто спросил, модель, prompt/completion/total
tokens, сколько входных токенов пришло из кэша промпта, оценка стоимости в
долларах, число раундов tool-calling, успех/ошибка.

Кэш промпта важен для расчёта: стабильный префикс (системный промпт + описания
инструментов) переиспользуется, и кэшированный вход стоит на порядок дешевле
обычного. Оценка без учёта кэша завышает стоимость в разы, поэтому ставки
кэшированного и свежего входа считаются раздельно (`usage.PRICES_PER_1M`).

Служебные поля ответов Базы Знаний (`themes`, `authors`, `status` и прочие) в
модель не передаются — они не нужны ни для выбора статьи, ни для ответа, но
платятся как входные токены каждый раунд. Замер: ответ `search_content`
похудел с 8086 до 4265 символов, средняя стоимость запроса — с ~$0.006 до
~$0.0028.

Команда `/stats` в боте показывает агрегат (транзакции, токены всего и по
пользователям), но отвечает **только** тому, чей Telegram ID указан в
`ADMIN_TELEGRAM_ID` (`.env`) — если не задан, команда молча игнорируется для
всех, в том числе для тебя.

## Файлы

| Файл | Назначение |
|---|---|
| `bot/main.py` | Точка входа, long polling, разбор апдейтов Telegram, `/stats`, `/kb_ask` |
| `bot/llm.py` | Цикл LLM + tool-calling поверх MCP-инструментов |
| `bot/mcp_client.py` | Клиент к MCP Базы Знаний (Streamable HTTP, read-only) |
| `bot/usage.py` | Счётчик транзакций/токенов (запись + агрегация для `/stats`) |
| `bot/group_gate.py` | Гейт группового чата (@упоминание / reply на бота) |
| `bot/config.py` | Переменные окружения |

## Не решено / предстоит

- Разграничение доступа по странам на стороне Базы Знаний: у read-инструментов
  KB нет параметра сужения по пространству, поэтому «страна партнёра» сейчас
  живёт только в системном промпте. Жёсткий вариант — постфильтрация
  результатов по `spaceId`.
- Нужна ли запись в Базу Знаний вообще, или только чтение навсегда — сейчас
  read-only.
- Тесты: сейчас поведение проверяется прогоном реальных вопросов через
  `llm.answer_question`, автотестов на разбор ответа и гейт чата нет.

Заметки по конкретному развёртыванию (хост, пути, эксплуатационные детали)
держатся вне репозитория.
