# Dodo KB Bot

Telegram-бот, который отвечает на вопросы по внутренней Базе Знаний Dodo:
находит статьи, читает их и даёт ответ по существу со ссылками на источник.
Партнёру не нужен ни логин в Базу Знаний, ни личный токен.

```
/kb_ask настройка кассы ресторана
   ↓
Настройка касс выполняется в разделе «Точки продаж — Кассы» в «Додо ИС»…

Статьи:

Настройка касс в «Додо ИС»
Создание и редактирование кассы, настройка ККМ, способов оплаты, primary-кассы.
Ссылка: https://knowledgebase.dodois.io/next/article/<spaceId>/<articleId>
```

## Поверхности

| Поверхность | Что делает |
|---|---|
| `/kb_ask <вопрос>` | Задать вопрос по Базе Знаний в групповом чате |
| `@упоминание` / reply на бота | То же самое без команды (упоминание требует выключенного Group Privacy Mode) |
| `/kb_info` | Справка для партнёров: как пользоваться ботом (ru/en) |
| `/start` | Короткое приветствие |
| `/stats` | Расход транзакций, токенов и денег — только владельцу (`ADMIN_TELEGRAM_ID`) |

Справка для партнёров — [docs/PARTNER_GUIDE.md](docs/PARTNER_GUIDE.md) (тот же
текст, что выдаёт `/kb_info`).

## Как это работает

1. Партнёр задаёт вопрос в групповом чате.
2. LLM (`gpt-5.6-luna`, задаётся `OPENAI_MODEL`) ищет статьи через MCP-сервер
   Базы Знаний, читает подходящие целиком и формулирует ответ.
3. Ответ проходит постобработку и уходит в чат вместе со ссылками на статьи.

**Поиск идёт в две фазы, и это важно.** `search_content` возвращает только
заголовки и короткие обрывки текста (excerpt) — по ним модель обязана лишь
*выбрать* статьи, а затем прочитать их целиком через `get_content` и отвечать
только по полному тексту. Без этой фазы модель домысливает шаги, которых в
статье нет (проверено — получались «советы» вместо инструкции).

**Поиск в Базе Знаний — по ключевым словам, не по смыслу**, а часть материалов
существует только на английском. Поэтому для международных тем промпт требует
второй запрос с английскими терминами.

**Приоритет источников.** Партнёры международные, поэтому на вопрос без страны
общие и международные материалы идут выше локальных (РФ, Казахстан, Беларусь):
у локальных другое законодательство, провайдеры и оборудование. Если названа
конкретная страна — берутся материалы только по ней, а если по ней ничего нет,
бот говорит это прямо, а не подставляет другую страну.

## Стек

| Слой | Технология |
|---|---|
| Бот | Python 3.12, aiogram 3, long polling (без вебхука) |
| LLM | OpenAI, tool-calling, `temperature=0` для предсказуемости ответов |
| MCP-клиент | официальный `mcp` (Python SDK), Streamable HTTP, read-only |
| Хостинг | Docker Compose на своём сервере |
| Хранилище | своей БД нет; локально копится только счётчик расхода (`usage.jsonl` в Docker volume) |

Архитектура и цикл tool-calling — по образцу `handleAsk` из проекта Swarm Brain,
адаптированы под чужой MCP вместо собственной базы.

## Быстрый старт

```bash
cp .env.example .env
# впиши BOT_TOKEN (@BotFather), OPENAI_API_KEY, KB_MCP_TOKEN (выдаёт админ БЗ)

docker compose up -d --build
docker compose logs -f bot
```

Полный список переменных окружения с пояснениями — в
[.env.example](.env.example); там же ограничения частоты и список разрешённых
чатов.

## Тесты

```bash
python3.12 -m venv .venv
./.venv/bin/pip install -r bot/requirements.txt pytest
./.venv/bin/python -m pytest tests -q
```

Покрыты чистые функции, где уже случались регрессии: гейт группового чата,
проверка и нормализация ссылок, вычистка Markdown, подписи по языку, разворот
схемы MCP и выброс служебных полей, расчёт стоимости с кэшированным входом,
нарезка длинных ответов. Сети и ключей тесты не требуют. На каждый push
прогоняются в CI (`.github/workflows/tests.yml`).

## Безопасность

| Контроль | Как сделано |
|---|---|
| Токен Базы Знаний | один сервисный PAT только в `.env` на сервере; партнёры его не видят |
| Только чтение | без заголовка `Mcp-Mode: Write` сервер БЗ вообще не отдаёт write-инструменты, то есть запись физически недоступна |
| Личка | закрыта для вопросов: бот работает в групповых чатах |
| Список чатов | `ALLOWED_CHAT_IDS` — если задан, в остальных чатах бот молчит |
| Ограничение частоты | пауза на пользователя + потолок вопросов на чат в час (`bot/limits.py`): каждый вопрос стоит денег |
| Ссылки в ответе | пропускаются только ссылки на Базу Знаний и адреса, дословно встречавшиеся в текстах статей; выдуманные вырезаются, превью ссылок отключено |
| Ответы модели | Markdown вычищается, подписи приводятся к языку ответа — партнёр не видит сырой разметки |
| Контейнер | работает под непривилегированным пользователем, права на запись только у каталога учёта |
| Зависимости | версии закреплены точно |
| `/stats` | отвечает только `ADMIN_TELEGRAM_ID`; посторонним молчит, не подтверждая существование команды |
| Логи | контент Базы Знаний и тексты ошибок наружу не пишутся, в логе только имена инструментов и размеры ответов |

Сканирование — `aitriage scan .` (текущий результат: 100/100, блокирующих
находок нет). Отчёты пишутся в `aitriage-reports/` и в git не попадают.

## Учёт расхода

Каждый ответ дописывает строку в `usage.jsonl`: кто спросил, модель,
prompt/completion/total tokens, сколько входных токенов пришло из кэша промпта,
оценка стоимости, число раундов tool-calling, успех/ошибка.

Кэш промпта обязателен для расчёта: стабильный префикс (системный промпт +
описания инструментов) переиспользуется, и кэшированный вход стоит на порядок
дешевле обычного — оценка без его учёта завышает стоимость в разы. Ставки
считаются раздельно (`usage.PRICES_PER_1M`).

Служебные поля ответов Базы Знаний (`themes`, `authors`, `status` и прочие) в
модель не передаются: они не нужны ни для выбора статьи, ни для ответа, но
платятся как входные токены каждый раунд. Замер — ответ `search_content`
похудел с 8086 до 4265 символов, средняя стоимость запроса с ~$0.006 до
~$0.003.

| Файл | Назначение |
|---|---|
| `bot/main.py` | Точка входа, long polling, команды, разбор апдейтов Telegram |

| `bot/usage.py` | Счётчик расхода и оценка стоимости |

## Не решено / предстоит

Задачи ведутся в [Issues](https://github.com/GarroV/dodo_kb_bot/issues).
Основное:

- Разграничение доступа к материалам по странам на стороне Базы Знаний:
  у read-инструментов нет параметра сужения по пространству, поэтому
  «страна партнёра» живёт только в системном промпте.
- Часть статей находится только по английским терминам — сейчас это лечится
  инструкцией модели, а не кодом.
- Нужна ли запись в Базу Знаний вообще, или только чтение навсегда.

Заметки по конкретному развёртыванию (хост, пути, эксплуатационные детали)
держатся вне репозитория.
