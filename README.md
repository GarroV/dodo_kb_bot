# KB Partners Bot

Telegram-бот-прослойка для доступа партнёров Dodo Pizza (по странам) к внутренней
Базе Знаний (knowledgebase.dodois.io) — без выдачи партнёрам личных логинов или
личных MCP-токенов.

## Что это и зачем

Партнёр пишет вопрос боту на человеческом языке. Бот прогоняет вопрос через LLM
(gpt-4o-mini) с доступом к read-инструментам MCP-сервера Базы Знаний
(`search_content`, `get_content`, `get_space_content`, `get_announcements`,
`get_spaces`, `current_user`, `get_link_templates`, `preview_content`) —
LLM сама решает, идти ли в базу, какой инструмент вызвать и как сформулировать
поиск, а затем пересказывает найденное обычным языком со ссылками на источник,
а не отдаёт сырой JSON.

**Единая точка входа.** Один сервисный PAT-токен от Базы Знаний живёт только в
`.env` на сервере — партнёры его никогда не видят и не получают. Соединение
read-only: без заголовка `Mcp-Mode: Write` сервер Базы Знаний вообще не отдаёт
write-инструменты в `tools/list` (проверено вживую) — значит запись физически
недоступна из этого бота, а не просто отключена по договорённости.

**Кто может писать боту.** Список партнёров (`partners.json`, telegram_id → имя
+ страна) — единственный контроль доступа: кому вообще позволено разговаривать
с ботом. Сама База Знаний в read-режиме не разграничена по пространствам, так
что поле «страна» используется как контекст для LLM (в первую очередь искать
релевантное стране партнёра), а не как техническое ограничение доступа.

## Стек

| Слой | Технология |
|---|---|
| Бот | Python 3.12, aiogram 3, long polling (без вебхука — конвенция Muspelheim) |
| LLM | OpenAI gpt-4o-mini, tool-calling |
| MCP-клиент | официальный `mcp` (Python SDK), Streamable HTTP |
| Хостинг | Docker на Muspelheim, `C:\projects\kb-partners-bot` |
| Хранилище | нет своей БД — контент живёт во внешней Базе Знаний; единственное, что копится локально, — счётчик транзакций/токенов (`usage.jsonl` в Docker volume) |

Архитектура и цикл tool-calling — по образцу `handleAsk` из проекта Swarm Brain
(`supabase/functions/swarm-bot/handlers/knowledge.ts`), адаптированы под чужой
MCP вместо собственной Supabase-базы.

## Быстрый старт

```bash
cp .env.example .env
# впиши BOT_TOKEN (@BotFather), OPENAI_API_KEY, KB_MCP_TOKEN (выдаёт админ БЗ)

cp partners.example.json partners.json
# впиши реальных партнёров: telegram_id, имя, страна

docker compose up -d --build
docker compose logs -f bot
```

Добавить/убрать партнёра: правишь `partners.json`, затем `docker compose
restart bot` — пересборка не нужна (файл смонтирован, не запечён в образ).

## Счётчик транзакций и токенов

Каждый ответ партнёру дописывает одну строку в `usage.jsonl` (внутри Docker
volume `usage_data`, не в git): timestamp, кто спросил, страна, модель,
prompt/completion/total tokens, число раундов tool-calling, успех/ошибка.

Команда `/stats` в боте показывает агрегат (транзакции, токены всего и по
партнёрам), но отвечает **только** тому, чей Telegram ID указан в
`ADMIN_TELEGRAM_ID` (`.env`) — если не задан, команда молча игнорируется для
всех, в том числе для тебя.

## Файлы

| Файл | Назначение |
|---|---|
| `bot/main.py` | Точка входа, long polling, разбор апдейтов Telegram, `/stats` |
| `bot/llm.py` | Цикл LLM + tool-calling поверх MCP-инструментов |
| `bot/mcp_client.py` | Клиент к MCP Базы Знаний (Streamable HTTP, read-only) |
| `bot/partners.py` | Загрузка и проверка списка партнёров |
| `bot/usage.py` | Счётчик транзакций/токенов (запись + агрегация для `/stats`) |
| `bot/config.py` | Переменные окружения |
| `partners.json` | Реальный список партнёров (не в git — см. `.gitignore`) |

## Не решено / предстоит

- Конкретный список партнёров и стран — сейчас `partners.json` пуст, доступ
  закрыт всем, пока не заполнен.
- **Изоляция чтения по странам — не обеспечена технически.** Партнёр из Сербии
  может спросить про Россию и получить настоящий ответ: у read-инструментов KB
  нет параметра ограничения по пространству (в отличие от записи, где
  `Mcp-Write-Spaces` реально режет доступ). Системный промпт просит модель не
  путать страны и переспрашивать — это мягкая инструкция, не жёсткая граница.
  Если нужна жёсткая изоляция — понадобится смотреть точные схемы
  `search_content`/`get_space_content` (нужен настоящий PAT) и постфильтровать
  результаты по `spaceId`.
- Нужна ли партнёрам запись в Базу Знаний вообще, или только чтение навсегда —
  сейчас read-only.
- Групповые чаты — сейчас бот отвечает на любое сообщение в личке; если бот
  будет жить в общем чате, нужен гейт по тегу/reply (в Swarm Brain уже есть
  готовый паттерн — `lib/group-gate.ts`).
